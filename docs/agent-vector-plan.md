# 夜喵向量能力：调研与实装指导（2026-10-14）

> 用户需求：「实装 vector 向量（搜集 形成指导）」。本文件是【搜集】与【形成指导】的产物；
> 【实装】已按本文落地：`services/agent-vector.js` + `utils/agent-context.js` 接线 + `tests/agent-vector.test.js`。

## 1. 目标

给夜喵接入**向量语义召回**：用户开口时，从更早的记忆与「让你记住的事」里，
按语义相关性找回与今晚话题最相关的一两条，注入上下文——替代目前「只注入最近一条」的粗糙策略。

## 2. 搜集：可用基础设施盘点（2026-10-14 实测）

| 通道 | 探测方式 | 结论 |
|------|---------|------|
| 大赛模型网关 embeddings | `POST {baseUrl 同源}/v1/embeddings`（带 API Key 与验证码） | **无此端点**。请求被路由进 chat completions 校验器（400：缺 `messages` 字段）；换默认模型名请求同样 400；不指定模型返回 403「该令牌无权使用模型」 |
| 网关模型列表 | `GET /v1/models` | 仅 1 个模型：`deepseek-v4-flash-780k-local`，`supported_endpoint_types: ["openai"]`（仅 OpenAI 兼容 **chat** 能力），令牌只授权这一个模型 |
| 微信云开发 / 自建服务端 | 仓库全量检索 `cloud`/向量相关引用 | 项目为纯端内小程序 + 大赛网关 + OCR 代理（`mcp.zju.edu.cn` 仅版面解析），无云开发、无服务端、无数据库 |
| 第三方 embedding API | — | 无凭据；小程序请求域名白名单也不可控，排除 |

复现命令（不打印密钥）：
```bash
node -e '
const s=require("./services/secrets.js");
const base=s.modelGateway.baseUrl.replace(/\/chat\/completions$/,"");
fetch(base+"/models",{headers:{Authorization:"Bearer "+s.modelGateway.apiKey}})
  .then(r=>r.json()).then(b=>console.log(JSON.stringify(b.data)));
fetch(base+"/embeddings",{method:"POST",headers:{"Content-Type":"application/json",Authorization:"Bearer "+s.modelGateway.apiKey},
  body:JSON.stringify({input:"测试"})}).then(r=>console.log(r.status, r.statusText));
'
```
**结论：真实 embedding 服务不可用（当前与可预见版本内）。** 向量能力必须在端内自足实现，且不能联网。

## 3. 方案选型

| 方案 | 可行性 | 取舍 |
|------|--------|------|
| 网关 embedding | ✗ 实测无端点 | — |
| 云端向量库（云开发/自建） | ✗ 无基础设施，且记忆为隐私数据不离端 | — |
| chat 模型代生成向量 | ✗ 成本高、维度不可控、结果不稳定 | — |
| **端内轻量向量（本方案）** | ✓ 零依赖、零网络、毫秒级 | 词面近似而非真语义（见 §7 局限） |

端内方案核心：**特征哈希（hashing trick / 随机投影）**把短文本映射为 256 维 L2 归一化稠密向量，
余弦相似度召回。对应经典向量空间模型，接口与真实 embedding 完全同构（§8 可一行替换）。

## 4. 引擎设计与实测校准

参数（`services/agent-vector.js`）：

- **维度 DIM=256**：96 维时哈希碰撞噪声过大（短查询假余弦可达 ~0.3），256 维压到可接受区间。
- **分词**：CJK 单字 + 相邻二元组（含跨词界，中文无空格时的最稳近似单元）；ASCII 字母/数字按词小写化。
- **权重**：二元组/词 1.0，单字 0.5，次线性词频 `1+ln(tf)`；FNV-1a 双 seed 定桶位与符号（signed hashing 降偏差）。
- **停用词**（25 条，时间/话语/人称类，如「今天/明天/最近/我们/什么」）：不进向量、不算证据。
  这是被实测逼出来的——「今天好累」最初会召回「今天晚霞很好看」（0.314）。
- **证据门槛（recall 默认开启）**：至少共享一个**非停用词二元组/词**才进入打分。
  单字查询（「唉」「睡不着」「恩」）靠碰撞即可拿到 ~0.3 假余弦，门槛是压噪关键；**宁缺勿噪**。
- **输出**：只取 `score ≥ minScore` 且 `> 0` 的前 `limit` 条；调用方取 `limit=2, minScore=0.15`。

实测分数分布（26 对样本；复核：`node tools/vector-calibration.js`）：

| 类别 | 区间 |
|------|------|
| 真实相关对（门槛通过） | **0.190 ~ 0.696**（如「明天要考试了，好慌，完全睡不着」↔「因考试焦虑而失眠」=0.190；「我最近总是半夜醒」↔「最近总是半夜醒来睡不着」=0.696） |
| 无关对（门槛拦截，残余最大） | ≤ **0.167**（「今天好累」↔「今天晚霞很好看」，被停用词拦下） |
| 无关对（门槛通过，合成模板类） | 0.318（「明天要考试了」↔「明天要去春游」——「天要」跨词界碎片穿门，见 §7） |
| 单字/超短查询 | 全部静默（门槛拦截） |

`minScore=0.15` 的取值：低于相关对下界（0.190）留余量，高于被拦噪声无意义；门槛通过类噪声由 §7 披露兜底。

**无持久化设计**：向量不入 storage。语料只有几十条 ≤60 字短句，每次发送现场重算（毫秒级），
天然一致、无需迁移、免缓存失效——这也是隐私面最小化（不新增任何落盘数据）。

## 5. 集成点

```
pages/agent/index.js:398  runAgentTurn() 取 answers 末位为本轮用户消息
pages/agent/index.js:425  agentContext.buildUserContext(Date.now(), lastUserMessage)
utils/agent-context.js   buildRelatedMemoryLine(userMessage)：
  语料 = 更早的记忆摘要（recall()[1..]）+ 第 6 条起的 facts
  排除「最近一条记忆」与「前 5 条 facts」（已由既有两行直接注入，不重复引用）
  命中则追加一行：「想起的旧事（相关才自然提一句，不相关就忽略）：…」
```

- **门控**：沿用设置页「夜喵记忆」开关（`nightPreferences.memoryEnabled`），关闭即无召回行。
- **失败静默**：任何存储/计算异常都被 `safeRead` 兜底，上下文退化为现状，对话不受影响。
- **不改变既有行为**：`buildUserContext(now)` 旧签名兼容（无 userMessage 即无召回行）；
  其余上下文行（呼吸/睡眠/日记/最近记忆/facts/约定/人格）逻辑未动。

## 6. 安全与合规

- 记忆是隐私数据：召回全程端内计算，不经过任何网络请求（比现状更保守，未新增数据外流面）。
- 「清除个人记录」即清空语料，召回自动失效（向量不落盘，无残留）。
- 召回行带「不相关就忽略」指令，配合既有上下文总则（不罗列、不监控感），避免生硬引用。
- 不改动对话规则、危机干预、推荐机制等任何既有红线。

## 7. 已知局限（如实披露）

1. **词面近似而非真语义**：「舍友」↔「室友」、「打游戏」↔「太吵」这类同义/改写不召回（实测样本中 2 对）。
   行为是「宁缺勿噪」——漏召回退化为现状，不产生错误注入。
2. **合成模板类误召回**：两条记忆同为「明天要X」骨架时，「天要」跨词界碎片可使无关对通过门槛（0.318）。
   真实语料（模型生成的困扰摘要 + 用户要求记住的事项）几乎不产生此类模板；线上若出现，
   优先扩充停用词表或给该片段降权。
3. **阈值是经验值**：基于 26 对样本校准，语料分布显著变化（如英文为主）需重新校准。

## 8. 升级路径（真实 embedding 接入时）

接口已按可替换设计：`embed(text) → 归一化向量`、`cosine`、`recall` 三层独立。

1. 网关/新服务出现 embeddings 端点时：替换 `embed()` 实现（网络版 + 本地缓存回退），维度改由服务端决定；
2. 真实语义向量下**关闭证据门槛**：`recall(..., { requireShared: false })`（门槛是为词面近似补的精度补丁，
   真向量不需要它来挡「今天好累」这类噪声）；
3. 届时向量值得持久化（真实 embedding 有网络成本），storage schema 增加 `vec` 字段与惰性迁移；
4. 可复用场景：书卡/专家卡检索、日记与梦境的语义搜索（当前语料太小，暂不接入）。
