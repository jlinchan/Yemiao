# 夜喵 Agent 回答质量修复记录（2026-10-17 深夜）

> 用户反馈「AI 回答质量不高」。本文记录**实测驱动的诊断与修复全过程**：
> 探针直连网关采样 → 定位稳定复现缺陷 → 分层修复 → 复测收敛。
> 网关仅提供 `deepseek-v4-flash-780k-local` 一个模型（`GET /v1/models` 确认），
> 无换模型余地，全部改进只能来自 prompt 工程与端内确定性逻辑。

## 1. 诊断方法

`node -e` 临时探针（`.workbuddy/tmp-quality-probe*.js`，已清理）：
用 `agentClient.buildSystemPrompt` 组装**与线上完全一致**的 prompt，
POST 大赛网关（stream:false, temperature:0.7, max_tokens:600），
每组场景跑 3 次——**同一 prompt 两次采样结论相反**的现象本身即是重要证据（模型行为是概率性的）。

## 2. 三个稳定复现的缺陷

| # | 缺陷 | 复现率 | 证据（修复前采样） |
|---|---|---|---|
| 1 | `@@REC@@` 推荐标记丢失 | 3/3（另一轮 0/3） | 用户「我想静静睡一觉」→ 收尾文本完美，标记从不输出；同 prompt 两次采样分别 3/3 ✓ 与 0/3 ✗ |
| 2 | 专家满载滑向分析式追问 | 3/3 | 亚隆视角三次均以「是怕考砸，还是怕考砸之后某个画面？」式二选一结尾，违背「一次一个开放问题 + 不说教」 |
| 3 | 满载回复变薄 / 多余空行 | 出现 | 阿德勒+CBT-I 双卡（prompt 7454 字）只回 30 字；句间插空行与双空格 |

基础场景（无专家无书卡，4385 字）质量良好，说明问题是**负载与协议竞争**引发的：
flash 模型指令遵循弱，7000 字 prompt 里 REC/PUSH/ASK/DO/SAFE 五套协议 + 双卡框架互相竞争注意力。

## 3. 修复方案（三层）

### 3.1 推荐机制：prompt 强化 + 端内确定性兜底（服务层 `agent-client.js`）

**prompt 层**（`buildSystemPrompt`）：
- 「推荐机制（重要，必须遵守）」→「**每次回复都必须做的二选一，不是可选项**」——把可选附加物改为强制决策；
- 触发条件从抽象描述改为**关键词清单**：想睡/想安静/想休息/晚安/困了/累了/明天再说/谢谢你今天/差不多了/先这样…；
- 示例改为贴近失败案例的「我想静静睡一觉」，并强调「**出现信号就输出，哪怕正文很短**」。

**端内兜底**（`buildFallbackRecommendation`，与安全门同架构：模型主导、端内补位）：
- 强信号正则：`想[^标点]{0,3}睡`（覆盖「想静静睡一觉」这类不连续说法）/`睡[一觉吧]`/`睡觉`/`晚安`/`困了`/`想安静`/`想休息`/`明天再说`/`谢谢你今天`/`先这样`；
- 匹配前剥否定（不想睡/没想睡不算）；「睡不着」是诉求不是收尾，**留给模型判断**（避免开场倾诉就被推卡）；
- 弱信号（累了/好累）不收——仍由模型按「倾诉是否充分」判断；
- 命中且提到 室友/吵/噪音/键盘/打游戏 → 白噪音挡噪音；其余 → 雨声；
- 模型自己出牌时**不覆盖**；三条完成路径（流式成功/非流式成功/中断保留残文）都过兜底，规则引擎回退路径不动（guide 自有推荐逻辑）。

### 3.2 专家/书卡：用量纪律 + 提问纪律（`experts/registry.js`、`books/registry.js`）

包裹层（注入段外层）新增，放在**规则首条**（flash 模型对段首最敏感）：

- **用量纪律**：先接住用户此刻的情绪与具体细节，再决定是否带入视角；一次回复最多轻轻用一个框架概念（一两句带过），不展开分析、不连环追问、不给用户的问题定性；用户明显只想被陪伴时就不用框架；回复长度仍按对话规则，输出连贯段落不插空行。
- **提问纪律**（专家）：结尾最多一个轻轻的开放式邀请；禁止「是A还是B」二选一提问，禁止追问根源与过去，不要求用户自我分析。
- **节奏示例**（专家）：接住一句 → 视角一句 → 轻邀请。示例域用「答辩」避开「考试」——初版示例用考试场景，被模型 **3/3 逐字照抄**开头，换域后照抄消失。

### 3.3 基础对话规则（`agent-client.js`）

- 新增「结尾最多一个轻轻的开放式邀请；禁止二选一提问，禁止让用户自我分析」——二选一是**模型通病**，基础模式的长多轮采样也有（「想先哄自己睡，还是想再跟他说一次？」），不只专家模式。
- 新增「输出连贯的段落：句子之间不插入空行、不连续换行、不堆多余空格」。

- 单元测试锁定的关键行为：
  - `buildFallbackRecommendation('我不想睡，想再陪你聊会儿')` → null（否定不算信号）；

  - 流式路径：模型只回正文 + 用户说「我想静静睡一觉」→ onComplete 带 recommendation。

## 6. 经验（可迁移）

1. **flash 模型的标记触发是概率性的**——任何「模型输出协议标记」的关键功能都要有端内确定性兜底，不能只靠 prompt。本项目安全门已是此架构，本次 REC 对齐。
2. **示例会被逐字照抄**——few-shot 示例的场景域要避开待测场景，否则回复开头千篇一律。
3. **「禁止清单」比「倡导清单」有效**——「不说教」无效，「禁止二选一提问/禁止让用户自我分析」有效。
4. **负载稀释真实存在**——7000 字 prompt 下同样的模型同样的话，回复长度和框架使用率都下降；剂量纪律（最多一个概念）比堆框架更有效。
5. 诊断质量问题的正确姿势：**探针直连 + 同 prompt 多次采样**。单次采样会把概率波动误判为修复/回归。
