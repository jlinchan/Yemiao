# 夜喵 Agent 增强方向调研（2026-10-18）

> 用户需求：「看看 Agent 方向还有什么可以值得增强的，可以查看 GitHub 或其他好的，现在功能还是有限。」
> 本文件是【搜集】与【形成指导】的产物；不含实装。落地顺序建议见 §6。

## 0. 约束（所有方向的前提）

- 唯一 AI 通道 = 大赛网关：OpenAI 兼容 chat、单模型 `deepseek-v4-flash`、无 embeddings、无原生 function calling。
- 无服务端、记忆隐私不离端、主包余量 49.9KB（加素材先跑 `tools/pack-budget.js`）。
- 测试基线：`node --test tests/*.test.js` 372 通过 + 6 todo，改动后必须全绿。
- 已吸收过的外部机制（不重复立项）：mem0 冲突消解（agent-memory sameTopic）、Generative Agents 三因子排序（agent-context 0.6/0.25/0.15）、女娲/book-to-skill 蒸馏管线（专家/书卡）、情绪安全硬门（safety-gate）。

## 2. 增强方向（P0：端内可落地，价值最高）

### 2.1 AI 定制睡前故事（新技能 `bedtime_story`）

- **依据**：晚安AI、Sleepytale、月光故事等产品把「按用户心境实时生成舒缓故事 + 柔和朗读 + 白噪音」作为睡前场景第一刚需；夜喵完全缺位。
- **差异化**：夜喵独有的记忆让故事可以「编织今晚的主题」——用户今晚倾诉了考试焦虑，故事就围绕「放下今晚的卷子」的意象展开（不点破、不分析）。
- **落地形态**：新增 `skills/bedtime-story.js`（技能清单自动进 prompt）；长文本流式输出 + voice-service TTS 朗读 + 与环境声同开；技能 prompt 写死低刺激内容规则（无冲突/惊吓/强情节转折，篇幅 300-500 字，节奏渐缓收尾）。
- **改动面**：skills 新文件 + registry 注册 + agent-client 的标记互斥规则（见 §2.5）+ TTS 长文本分句。
- **风险**：单条 max_tokens 600 是故事长度的硬上限，需评估是否放宽该技能单独的 max_tokens（网关是否支持按请求调整——支持，参数本来就在请求体里）。

### 2.2 记忆整理 / 核心记忆（对标 Letta sleep-time compute）

- **依据**：MEMORY_LIMIT=8 的滚动摘要会挤掉 7 天前的重要旧事；Letta 的 core memory 概念 = 恒在上下文的小型高价值记忆块；其 sleep-time compute = 空闲期后台整理。夜喵有天然的「打开时/晨间」空闲窗口。
- **落地形态**：`agent-memory.consolidate()`——当 `recall()` 中存在 ≥5 条 7 天前的摘要时，用网关把它们蒸馏成 1 条「长期画像」（≤40 字，如「这段时间在准备考研，凌晨 1 点后难入睡，最近和室友关系缓和了」），存入新 storage key `agentCore`（1-3 条），每次 `buildUserContext` 常驻注入；被卷积的旧摘要随之可安全淘汰。这是把「记忆容量瓶颈」转化为「记忆卷积」。
- **改动面**：agent-memory 新函数 + agent-context 注入一行 + 夜喵记忆页展示 + 测试。
- **边界**：蒸馏失败静默回退（现状不变）；「清除聊天记忆」同步清空 core。

### 2.3 情绪标注与情绪轨迹（对标 MindFlow / Replika「patterns, not just facts」）

- **依据**：陪伴类产品的共识是「记住模式而不只是事实」（institutepm 设计原则 2）；夜喵记了「聊到什么」，没记「情绪如何走」。
- **落地形态**：端内轻量情绪词典（同 safety-gate 架构：确定性规则、零请求），每轮用户消息归入 5-7 档（平静/低落/焦虑/烦躁/疲惫/危机由安全门接管），落 `agentMoods`（时间戳+档位）；晨间报告与上下文可注入「你这一周的情绪曲线：前半周比较紧绷，这两天松了一些」。词面向量可复用 agent-vector 做近义扩展。
- **改动面**：新 service（约 100 行）+ agent-context 注入 + 夜喵记忆页曲线展示（可选 canvas，注意包体）。
- **红线**：情绪数据属于个人记录，随「清除个人记录」删除；不给情绪下定义、不诊断。

### 2.4 陪伴偏好学习闭环（把 agent-reviews 从记录变成信号）

- **依据**：Mem0 2026 报告把 procedural memory（「怎么陪伴这个用户」）列为第三类一等记忆；夜喵已收集赞/踩+理由（agent-reviews），但只展示在 memory.md，未回流到行为。
- **落地形态**：`buildUserContext` 增一行——从近 10 条评价里端内聚合出「用户反馈」（如踩的理由多次出现「说教感」→ 注入「近期用户反馈：希望少一点建议式表达」）；规则式聚合即可，无需调用模型。
- **改动面**：agent-context + 一个聚合函数 + 测试；零新存储。

### 2.5 技能协议：允许「回复 + 多技能」（解锁组合体验）

- **依据**：竞品的「故事+白噪音同步」是组合动作；当前协议四标记互斥、一次一个 @@DO@@，模型技术上无法表达「边讲故事边下雨声」。
- **落地形态**：@@DO@@ 的 payload 支持数组（向后兼容单对象）：`@@DO@@{"skills":[...]}`，端内按序执行各技能；prompt 规则限定「最多 2 个且需场景耦合」。这是 sleep 故事的前置依赖。
- **改动面**：skills/registry.parseSkillCall + agent-client.splitResponse + 技能执行循环（需要确认型技能时取第一个 confirm）+ 测试。

## 3. 增强方向（P1：端内可落地，次优先）

- **晨间回顾报告**：agent-port 六板块快照 + 昨夜情绪 + 寄存心事 + 未完成约定 → 打开时一段 ≤150 字的「昨夜小结 + 今日一句」。心事寄存从「用户主动取回」升级为「晨间自动送回」，闭环感最强；与 morning-checkin 技能合并实现。
- **睡眠效率统计（CBT-I 数据层）**：睡眠记录已有 bedTime/wakeTime/duration，补「近 7 天睡眠效率 + 就寝变异性」的端内计算（对照 Sleep-Assistant 小程序）；只呈现数据与书卡知识转述，不做处方（perlis-cbti 书卡 boundaries 已声明「不是诊疗」）。
- **CBT 微干预技能 `reframe`**：把 MindFlow 的四步状态机做进对话（@@ASK@@ 选项引导情绪命名 → 端内规则识别思维歪曲类型 → 夜喵用书卡口吻带一次平衡思维）。作为技能实现，权限默认 confirm。
- **夜喵陪伴连续性**：Replika 式「关系不是每次从零开始」——已有的开场白机制增强：按记忆/约定/时段生成 3 种不同开场（引用 core 记忆、昨夜约定、连续陪伴天数徽章）。

## 4. 架构决策项（需要先决策再立项）

- **微信云开发（CloudBase）**：解锁三个当前做不到的能力——①订阅消息定时推送（agent-tasks 的到点提醒从「打开补发」变真推送，REMINDER_TMPL_IDS 已预留）；②真实 embeddings（agent-vector-plan.md §8 的升级路径可一键替换 embed()）；③长会话存档。代价：与「隐私不离端」承诺有张力。折中方案：只有「推送触达」走云，记忆与对话数据仍全部端内。

## 5. 负空间（调研过、明确不建议）

- **端内跑本地模型**（Mate 项目的 llama.cpp + 3B 模型路线）：35MB 模型包体塞不进 2MB 小程序，且网关已可用——排除。
- **多 agent 框架 / 通用 agent 运行时**（LangChain 等）：与原生小程序运行时和 2MB 包体冲突，夜喵的「标记协议 + 端内目录」已是该约束下的合理解。
- **知识图谱记忆**（Zep/Graphiti 路线）：夜喵的事实规模（15 facts + 8 摘要）远够不到图检索的收益门槛，sameTopic 合并 + 三因子排序已是恰当复杂度。
- **视觉形象/视频通话**（Replika 2.0 路线）：无服务端推流能力，且与低刺激睡前场景相悖。

## 6. 建议的落地顺序

1. **2.5 多技能协议**（前置依赖，半天量级）→ 2. **2.1 睡前故事**（功能补强最直接，竞品已验证）→ 3. **2.2 记忆整理**（补记忆短板）→ 4. **2.3 情绪轨迹** + **2.4 偏好闭环**（喂给晨间回顾）→ 5. **P1 晨间回顾报告**（把 2.2/2.3/心事/约定串成出口）。
2. 每项单独成批，对齐既有惯例：规划 → 实装 → `node --test` 全绿 → 真机验收；安全门与危机协议在所有改动中保持最高优先级且不被新能力改变。
3. 云开发（§4）建议与队友/指导老师对齐产品定位后再决策。
